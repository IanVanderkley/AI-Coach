# Account username changes (Batch 22D)

Account settings now owns the canonical username. Valid names use 3–20 ASCII letters, numbers or underscores. Names are case-insensitively unique across public and anonymous accounts. The first explicit change is immediately available; subsequent changes, including case-only changes, require 30 days (720 hours) from the previous successful change. Exact no-ops do not consume the cooldown. Old names are released.

The existing `ranked_leaderboard_profiles` row is the canonical source; the navbar uses its owner-scoped RLS read. Auth metadata is only a requested initial name, not an authorization or rename mechanism. Confirmed new accounts with a conflicting/invalid requested name receive a random `Player…` alias rather than a failed confirmation; they can rename immediately. Existing profiles retain their names, visibility, rating and counts. Confirmed accounts with no profile are initialized with zero games and are not eligible for the boards. The migration fails if pre-existing case-insensitive duplicates exist; resolve explicitly instead of overwriting user names.

`PUT /api/leaderboard/preferences` accepts exactly one of `{username}` and `{isAnonymous}`, verified same-origin and owner-scoped. Older settings tabs that send both fields must refresh. SQL enforces uniqueness and timestamps, even if an older API writes the table. No browser write grants, no changes to XP, game history or Elo. Anonymous mode does not release a username. Users can infer a name is unavailable but cannot learn the owner or privacy setting. There is no new distributed limit on failed username attempts; existing successful-change cooldown is enforced in the DB.
