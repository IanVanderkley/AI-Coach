# Account lifecycle and Coaching grades (Batch 17)

## Configuration before email testing

The Supabase SSR client uses PKCE. In the staging project's Authentication > URL Configuration, set the Site URL to the intended trusted staging application origin. Add exact redirect URLs for local development and the specific staging deployment, each ending in `/auth/callback?kind=signup`, `/auth/callback?kind=recovery` and `/auth/callback?kind=email`. Do not add broad production wildcards or disable verification. Enable email confirmation and check secure email change, password policy (minimum eight characters recommended), and SMTP delivery configuration. Use the normal Supabase confirmation and recovery email templates with the confirmation URL; do not send tokens to external sites. Open links in the same browser and origin where requested (PKCE). Verify the configured templates actually return the authorization code. If a link expires or the verifier is missing, request another. No production settings have been changed.

## Account management

Sign-in, signup, confirmation resend, password reset request, PKCE callback, authenticated password update, email-change confirmation, and sign-out everywhere are provided. Existing shorter passwords are accepted for sign-in; new passwords require at least eight characters and matching confirmation. Password updates revoke refresh sessions globally. Default navbar sign-out affects only this browser. Email requests give non-enumerating responses. Provider-side email limits and delivery settings still apply.

Account deletion is disabled unless `ACCOUNT_DELETION_ENABLED=true` is explicitly set on the server. Keep disabled until a disposable staging account has passed the deletion acceptance checks. The endpoint rejects cross-origin requests, caps JSON size, requires typed DELETE plus password, checks the current authenticated identity against fresh password authentication, revokes sessions, and hard-deletes only that identity using the existing server-only admin client. Never put the secret key in browser variables. The staging foreign-key audit confirmed CASCADE relationships for user preferences, Practice games/moves/totals, Ranked matches/results, leaderboard profiles, Elo events, and XP records. Other non-FK data, storage ownership, backups and retention require review before claiming complete deletion. Existing access JWTs can remain valid until expiry; deletion revokes refresh sessions but does not guarantee instant invalidation at every endpoint. Do not test against a real account. Enable on local/staging only for acceptance testing, and keep public release blocked until verified.

## Coaching grades

Default: calculate grades for retained Practice history one recording at a time, yielding between recordings and pausing when a review opens. This is local deterministic scoring, not a paid AI request or a generated lesson. Scores may take time to appear for long histories; a failed recording is unavailable and a game with insufficient evidence is not graded. Turning off automatic grades in Settings reveals grades only after reviewing a game in the current visit. Signed-in preference uses non-authorizing user metadata; guests use local storage. Existing replay view and tooltip settings remain browser-local. Grades are recomputed from saved games on a new visit/device, not stored as permanent Ranked results.

## Manual staging acceptance (not completed by this package)

1. Create a disposable account; confirm its email, check wrong password and unverified email messages, resend confirmation. Verify confirmation link and callback.
2. Request recovery for that account and a nonexistent address; check generic feedback. Open the valid link in the originating browser. Reject expired/reused links and mismatched passwords; update password and confirm old password fails and new password works.
3. Change email; verify required confirmation messages and actual login address change. Sign out locally and confirm another device remains signed in; sign out everywhere and confirm refresh fails on both devices.
4. Save coaching style, goals and grade visibility on browser A. Finish a Practice game and a Ranked match. Sign into the same account in browser B; compare settings, retained Practice games, lifetime statistics, XP, Ranked results and leaderboard visibility. Check another account cannot access them. Replay view and tooltips are intentionally local; guest games are tab-local until synced.
5. With deletion enabled only for a disposable staging account: reject wrong password, malformed confirmation, unauthenticated and foreign-origin requests. Confirm deletion with correct password. Verify associated rows are gone, public standings no longer show the deleted user, unrelated accounts are unchanged, and refresh/login fail. Verify storage and any remaining non-FK data separately. Disable the flag after the test until release approval.
