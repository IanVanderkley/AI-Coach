# Batch 26D — Ranked history grades

Recent Ranked Matches is on Coaching; Profile still uses its existing metadata-only summary. The existing automatic grade preference applies to Ranked and Practice. While the Ranked list is open, request one compact grade at a time, independently of the metadata list. Collapsing, navigating away, starting review or signing out cancels the worker; manual reviews display their own grade in the current Coaching session even when automatic grades are off.

The grade endpoint verifies the request origin, signed user identity, active session, existing read quota and a separate 12-per-minute per-account cache-miss quota. On a miss, it uses the existing completed owner-scoped Ranked recording reader and the same shared review scorer. Never accepts user board/grade input. The cache contains only match/user IDs, analysis version, grade, score and creation time, not the replay. A null score and grade means insufficient evidence; invalid recordings and transient errors remain unavailable and can be retried through history refresh. Cached reads are owner-scoped and do not rerun the scorer. Concurrent cache misses can duplicate computation but cannot overwrite a cached grade. No work occurs on the gameplay move path. No paid AI, Elo, XP or personalized saved report writes. The cache is service-only, immutable per match/version, with cascading match/account deletion and validation of terminal match provenance. The migration does not backfill. Changing shared analysis/scoring requires bumping the cache version and aligning parser/SQL grade thresholds if changed.

Apply locally first. Run the rollback-only SQL fixture as postgres on the local stack, full tests/typecheck/build and browser checks. The fixture checks cache structure and provenance, not grading accuracy; grading uses the existing verified review pipeline. Deploy cache migration before the new frontend/route; old code remains compatible. No ranked policy header change is required.
