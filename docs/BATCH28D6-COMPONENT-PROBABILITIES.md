# Batch 28D.6 — Component probability analysis

The explicit post-game advanced analysis now counts each connected clue component independently. Cells belong to the same component if a chain of visible clues connects them. Local count distributions are combined by mine count; each compatible assignment is weighted by the exact binomial number of unconstrained-cell arrangements. A cell's numerator uses its component's mine-hit distribution and the distributions of all other components. Player flags are not evidence. The original replay grading and standalone enumeration APIs remain unchanged.

Hard limits: 18 cells per connected component, 100,000 DFS nodes across all components, and 250,000 arithmetic work units for combining distributions and weights. Any limit discards all partial probability counts. Complete counts are exact decimal integers under a uniform compatible-layout model, not necessarily the actual game generator distribution. Exact zero-risk alternatives are labelled guaranteed safe, with the model explanation retained. Large connected frontiers can still be limited. Basic and advanced overlap rule proofs remain separate from probability counting.

Verification: exhaustive independent oracle on 2×2, 2×3 and 3×3 snapshots, analytic split frontiers on Beginner/Intermediate/Expert, independent full-board enumeration with multiple variable-mine-count components, work limits, flag independence, large integer counts, and deterministic replay-derived snapshots on all three difficulties. Benchmarks print timings as diagnostics rather than flaky time assertions. Synthetic and replay-derived fixtures do not represent all real gameplay. The on-demand UI remains synchronous; browser performance must be checked before considering a worker. No database, API, live gameplay, grading or deployment changes.
