# Ranked session guard

Claims mode verifies the token through Supabase getClaims, checks the signed authenticated subject, session UUID and expiry, and forwards the verified pair to a service-role-only seven-argument execute_ranked_move overload. The overload checks the live auth session, ownership, explicit session expiry, banned_until and deleted_at before delegating to the existing admission/move transaction. No extra HTTP round trip per move. Recovery checks the same live session before reading the board; that non-hot path adds one RPC. Default getUser callers retain the original six-argument RPC; new match creation remains getUser. This is not an application-wide revocation change or a check of every optional Auth inactivity/timebox setting. Already in-flight requests are not cancelled.

The narrow private SECURITY DEFINER lookup uses an empty search path and grants no browser roles access. The service role is trusted to forward only verified claims; neither user ID nor session ID comes from the request payload. Database permission or availability errors fail closed. The original RPC remains for existing deployments; never enable claims on an older unguarded build.
