# Batch 26B.2 — Private final-guess proof in PostgreSQL

The private immutable SQL proof enumerates candidate final safe locations using exactly 215 revealed safe clues. The board adapter validates the 40 mine positions, 215 distinct safe reveals, the first-click safe neighborhood and the actual mine hit. It ignores flags. The original generator uses UUID-randomized ordering of cells outside the first-click neighborhood; both possible worlds honor that same exclusion. Exactly two compatible layouts are a straight 50/50 under that random selection model. No hidden board data or candidate positions are exposed through an API.

The proof is **not connected to settlement**. The existing v4 status trigger executes before the last move is inserted in `ranked_match_moves`. It cannot simply read that move at its current timing. A later patch must establish the actual direct reveal inside the trusted transaction, preserve normal chord/win settlement and receipt idempotency, and update receipt validation and UI. Neither the migration nor this test changes any award, profile or match row. Both proof functions are private, SECURITY INVOKER, and revoked from PUBLIC, anon, authenticated and service_role.

Local only: generate a new migration with `npx supabase migration new ranked_final_guess_proof`, run the installer dry-run and apply, then `npx supabase db push` (no --remote). Run the generated SQL parity check using local psql with ON_ERROR_STOP and shell pipefail. The test uses temporary tables and rolls back; no player data changes. It compares 105 visible-board cases to the TypeScript reference and 13 adapter cases, checks role grants and confirms the existing v4 settlement function and write guard remain active. Full settlement and real match tests will be separate.
