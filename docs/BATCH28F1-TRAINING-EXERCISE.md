# Batch 28F.1 — Training exercise model and validation

Baseline: `a54a39e` (Batch 28E complete; 1,175 locally verified tests). This checkpoint is intentionally framework-independent; no route, component, migration, persistence or competitive rewards are changed.

## Exercise contract

`TrainingExercise` v1 describes one complete visible board: 2–8 rows and columns, public total mine count, a bounded identifier/title, a lesson difficulty label, a row-major array of revealed clue numbers (0–8), `covered` or `flagged` cells, and one objective. A difficulty label is a content-authoring classification, not measured player skill. There must be at least one clue and one covered square. Unknown fields, hidden mine layouts, answer keys, invalid targets and unsupported versions are rejected. The board is a standalone logical position, not necessarily a snapshot generated by the live game's opening rules. Cropping a larger board while retaining its global mine counter is not allowed.

- `reveal-safe`: accept any unflagged covered square that is safe in every compatible layout.
- `flag-mine`: accept any unflagged covered square that is a mine in every compatible layout.
- `classify-square`: classify one specified covered or flagged cell as safe, mine or uncertain. Uncertain requires at least one compatible layout of each kind.

`prepareTrainingExercise` strictly parses the definition, uses the existing exact component probability engine, requires complete nonempty layout enumeration, cross-checks every available deduction proof with exact counts, and refuses positions with no eligible solution. Rule proofs can support future hints, but a classification proven by enumeration need not have a local-rule certificate. The prepared data includes exact integer strings, not rounded probabilities. A flag is a player mark and is never proof. `assessTrainingAnswer` distinguishes invalid input, an incorrect valid choice, and a correct choice; it consumes a locally prepared exercise, not a client-authored solution. Recompute from trusted definitions on the server before persisting any future result. This is training, not an anti-cheat or competitive scoring interface.

## Verification

12 new tests cover parsing, invalid/sparse inputs, hidden data/answer-key rejection, contradictory clues, enumeration limits, all three objectives, multiple valid solutions, uncertainty, flags, invalid answer shapes, determinism, and an independent full-layout oracle over 408 valid 2x3 snapshots with 1,406 covered squares. The 8x8 limit and existing solver budgets bound the first release; positions that exceed the exact enumeration budget are rejected, not guessed. Full-size replay-derived exercises will require a separate design to preserve every relevant constraint. No paid AI or new dependencies. No UI in this checkpoint.
