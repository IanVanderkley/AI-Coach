# Batch 28E.3 — Historical learning trends

Pure, descriptive aggregation of the existing account-scoped saved reviews. Reuses `analyzeLearningReviews` to select valid current-version reports, one mode and difficulty at a time, excluding duplicates, conflicts and invalid summaries. No new replay work, hidden mine information, AI calls, persisted fields, rating changes or UI changes.

- Chronological points include actual game reference, completion date, outcome, counts of supported/mistaken/uncertain actions, decision accuracy and evidence coverage, recorded board clearance and mistake prevalence by type. A trailing five-game window is available only once five games exist. Accuracy is pooled across decisions, not a mean of per-game accuracy. Board clearance is the mean of recorded (rounded) per-game percentages. Zero assessed decisions gives null accuracy; no observed actions gives null coverage.
- Compare equal-size, non-overlapping oldest and newest halves of the selected window; leave out the middle game when the number is odd. At least five games per half and strictly separated completion timestamps are required for a comparison. Accuracy change additionally needs at least five assessed games and 20 assessed actions in each half. Other changes remain descriptive when accuracy lacks evidence. Rates use unrounded numerator/denominator and changes are signed percentage points. Display coverage and sample sizes with accuracy. Same timestamps within a period are ordered deterministically by the existing analytics ordering, not treated as evidence of a temporal change between them.
- Mistake prevalence is games with the recorded mistake divided by games in that period, not a per-opportunity error rate. Report observations only; do not infer mastery, causality, statistical significance or changes in underlying skill. Minimum sample thresholds are presentation choices. Saved reviews are a potentially selective sample, not necessarily all games played. Current solver grading and existing saved-review version remain unchanged.
- Later UI integration should use the existing private saved-review endpoint, show missing data as gaps and disclose that the chart describes saved reviews only. No authentication or provenance is established by these counter checks; callers must use existing account-scoped boundaries.
